# Правила для Pull Requests

> Соблюдаешь эти пункты - твой код попадет в проект с вероятностью >90%. Нет - закрою PR и забуду о нём.

## Перед созданием PR

1. **Запусти и протестируй.** Без этого PR не будет рассмотрен. Запусти проект, проверь основную логику, убедись что всё работает. Багфикс - проверь что баг исправлен. Фича - проверь что она работает и не ломает существующие.
2. **Совпадение стиля.** Код должен быть в стиле кодовой базы. Сомневаешься - сравни с существующими файлами. Стиль должен быть идентичен.
3. **Прочитай CONTRIBUTING.md.** Там общие правила для всех проектов экосистемы.
4. **Создай Issue сначала**, если фича выходит за рамки существующего функционала или требует обсуждения. Большие PR без предварительного обсуждения - это плохо.

## Код

### Ожидания от каждого PR

- **Типизация.** Везде, где это принято в проекте. Читаемые типы вместо `Any` там, где это возможно.
- **Логирование.** Используй общий логгер проекта. Логируй ключевые моменты: старт операций, ошибки, завершения, ретраи. Не логируй секреты.
- **Обработка ошибок.** Используй кастомные исключения/ошибки проекта вместо голых `Exception`. Оборачивай внешние вызовы в retry с backoff. Для неожиданных ошибок - логируй с трейсбэком.
- **Конфигурируемость.** Все параметры, которые может менять пользователь - через переменные окружения или конфиг-файлы с разумными значениями по умолчанию. Не хардкоди.
- **Безопасность.** Не коммить, не логируй, не выводи в вывод:
  - Токены, ключи, пароли
  - Сессии, номера телефонов, email
  - Ссылки с секретными параметрами
- **Устойчивость.** Любые внешние взаимодействия - через retry. Для долгих операций - задержки, рандомизация, human-friendly поведение.
- **Производительность.** Кэшируй часто используемые данные. Используй неблокирующий ввод-вывод и оптимальные настройки хранилища. Добавляй индексы где нужно.
- **Локализация.** Все пользовательские строки — через систему переводов, если проект многоязычный. Не оставляй хардкодные строки.

### Инфраструктура

- Для путей используй средства языка/ОС, а не конкатенацию строк.
- Файловые и сетевые операции - неблокирующие.
- Атомарная запись данных: временный файл + переименование.
- Бэкапы перед записью.

## Структура проекта

Следуй существующей архитектуре. Не выдумывай новую структуру модулей без обсуждения. Если проект монолитный - не дроби его без причины. Если модульный - не сливай всё в один файл.

Универсальные правила:

- Всю конфигурацию храни вне кода.
- Бинарники, кэш, сессии, базы данных, логи - в `.gitignore`.
- Лицензия - MIT, если не оговорено иное.

## Тестирование

Перед отправкой проверь:

- [ ] Проект запускается без ошибок
- [ ] Основные сценарии работают
- [ ] Обработка ошибок не ломает бота/приложение
- [ ] Логи корректные, без секретов
- [ ] Если менял схему хранения - существующие данные не потеряны
- [ ] Если добавляешь пользовательские строки - они переведены на поддерживаемые языки (советую использовать для переводов DeepSeek)
- [ ] Сборка/пакетирование работает (Docker, билд и т.д.)
- [ ] Пример конфига (`.env.example` и т.п.) обновлён, если добавлял новые параметры

## Описание PR

В описании укажи:

- Что изменил
- Зачем это нужно
- Как тестировал
- Ссылка на Issue (если есть)
- % использования ИИ, и какие ИИ были использованы (точные модели и провайдеры)

## Заголовок PR

Формат: `тип(опционально): краткое описание`

Примеры:

- `fix: исправить падение при пустом списке`
- `feat: добавить экспорт статистики`
- `refactor: вынести конфиг в отдельный модуль`
- `docs: обновить README с инструкцией`

Типы: `fix`, `feat`, `refactor`, `docs`, `test`, `chore`, `perf`, `style`, `ci`, `build`

## Что проверяется

- Соответствие стилю
- Работоспособность
- Отсутствие секретов
- Соответствие концепции проекта
- Обратная совместимость
- Влияние на производительность

## Если PR отклонён

Не обижайся. Если отклонение не по существу - задай вопрос. Если по существу - исправь и отправь снова.

## Запрещено

- PR с массовым форматированием без содержательных изменений
- Новые зависимости без обоснования
- Очевидные/бесполезные комментарии
- Чужой код без указания источника
