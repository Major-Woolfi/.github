# Issues

> Правила создания Issues. Соблюдаешь их - получишь ответ быстро. Не соблюдаешь - закрою как wontfix и забуду.

## Перед созданием Issue

1. **Поищи существующие.** Возможно, твой вопрос уже задавали. Используй поиск по Issues.
2. **Проверь документацию.** В README описаны основные концепции, архитектура и возможности. Если ответ там есть - не создавай дубликат.
3. **Обнови зависимости.** Если проблема может быть связана с устаревшими библиотеками - сначала обнови их и перезапусти проект.

## Типы Issues

### 🐛 Bug Report (баг)

Заголовок: кратко и понятно. Не `помогите`, а `Ошибка валидации при пустом списке участников`

В описании укажи:

- **Шаги для воспроизведения.** Что ты делал, чтобы получить баг.
- **Ожидаемое поведение.** Что должно было произойти.
- **Фактическое поведение.** Что произошло.
- **Логи.** Приложи логи. **Убери секреты** (токены, ключи, личные данные).
- **Версия runtime, ОС, способ запуска (Docker/нативно).**
- **Скриншоты/видео** если применимо.

### 💡 Feature Request (фича)

Заголовок: кратко. Не `добавь фичу`, а `Добавить экспорт статистики по трафику`

В описании укажи:

- **Проблему.** Что сейчас не так, какую боль решаешь.
- **Решение.** Как видишь реализацию.
- **Альтернативы.** Какие другие пути рассматривал.
- **Приоритет.** Насколько это важно для проекта.

### ❓ Question (вопрос)

Заголовок: кратко. Не `помощь`, а `Как настроить автоматическую выдачу подписок`

В описании:

- Контекст: что ты делаешь, чего хочешь достичь.
- Что уже пробовал.
- Где застрял.

## Заголовки

Правила:

- Первая буква заглавная
- Без восклицательных знаков и `СРОЧНО`
- Без тегов `[BUG]`, `[FEATURE]` — используй Labels (если они конечно есть в репозитории, т.к. могу забывать про них)
- На русском языке, если вопрос про код/фичу проекта
- До 70 символов

## Labels

Я сам расставлю labels после создания (наверное, если не забуду):

- `bug` - баг
- `enhancement` - улучшение
- `question` - вопрос
- `documentation` - документация
- `good first issue` - для новичков
- `help wanted` - нужна помощь
- `wontfix` - не будет реализовано
- `duplicate` - дубликат
- `invalid` - невалидный issue

## Закрытие Issues

Могу закрыть issue если:

- Ты не отвечаешь на вопросы 7+ дней
- Проблема не воспроизводится
- Feature request не вписывается в концепцию проекта
- Ты сам просишь закрыть
- Это дубликат
